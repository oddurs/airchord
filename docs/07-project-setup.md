# Airchord: getting the project production-ready

The code is in good shape; the *project* is not. There is no version control, no licence, no name
worth keeping, no deployment, and two agents writing to the same working tree with no undo.

## P1 — Version control, before anything else

This is urgent rather than important, and it comes first for one reason: **two sessions are editing
this tree right now and there is no history.** A mistake is currently unrecoverable.

1. **`git init` and commit the current state as-is** — including the broken typecheck in
   `engine.ts`. A baseline commit is a safety net, not a statement of quality. Do not tidy first;
   tidying without a baseline is the risky order.
2. **Audit `.gitignore`.** Already excluded: `node_modules`, `.next`, `.next-verify`, `certs`,
   `public/mediapipe`, `next-env.d.ts`, `*.tsbuildinfo`.
   - **Commit `src/lib/fixtures/gestures.json` (1.3 MB).** It is ground truth for the classifier and
     the thing that made accuracy testable. It belongs in the repo.
   - **Do not commit `public/mediapipe` (41 MB).** Regenerated by `npm run assets`; CI does the same.
     Pin the model URL and verify a checksum so the download cannot change under us.
3. **Branch and commit conventions.** Short-lived branches off `origin/main`, squash-merged.

## P2 — Two agents, one repo

The collision is not hypothetical — `engine.ts` currently fails to typecheck because both lanes
touched it. The fix is boundaries, not care.

1. **One branch ↔ one worktree ↔ one PR**, sited outside the tree at `../airchord-wt/<task>`.
2. **Name the integration points and treat them as contended**: `engine.ts`, `GestureSynth.tsx`,
   `useGestureSynth.ts`, `chords.ts`. Everything routes through these, so two lanes editing them
   concurrently is the one guaranteed conflict.
3. **Ownership by module, not by file-touching-luck.** Roughly: instrument core (`features`,
   `classifier`, `synth`, `overlay`) in one lane; practice mode (`songs`, `drums`, `transport`,
   `pose`, `practice`) in the other. Changes to the contended files land as small, fast PRs to
   `main`, merged before the next one starts.
4. **`main` must always typecheck.** CI enforces it; that is the whole point of P6.

## P0 — Rename to Airchord

Mechanical but wide: `package.json`, page title and metadata, the About dialog, README, docs, and
the Pages `basePath`. Worth doing immediately after the baseline commit so history is short.

## P3 — CLAUDE.md

The project has learned expensive lessons that are invisible in the code. They belong in a root
`CLAUDE.md` so neither lane relearns them:

- **Never set a threshold from a handful of frames.** It has failed three times: two thumb features
  and the major/minor lean. The captured dataset is ground truth; the video-frame feeds are a
  degraded proxy and are a smoke test only.
- **Measure, then change.** Every real defect here was found by rendering or replaying and reading
  numbers — clipping at 4.7×, the thumb offset that clamped every real value to zero, the neutral
  roll that made minor sticky. None was found by reading code.
- **No per-note envelope.** The right hand is the envelope; that is the instrument's identity.
- **Commands**: `npm run verify` (typecheck, tests, build), `npm run audio` (renders and measures
  the real signal path), `npm run dev` then `?capture` for the dataset tool.
- **Dev-only hooks**: `window.__handi`, `__capture`, `__audioCheck` — compiled out of production.
- **Attribution is a licence obligation**, not a nicety.

A scoped `src/lib/CLAUDE.md` can carry the DSP and classifier specifics so the root file stays short.

## P4 — Licence and attribution (blocks any public deploy)

This needs care, because we do not have the rights to relicense freely.

The original Gesture Synth licence permits adaptation for **personal, educational and
non-commercial** use **provided credit is given**, and reserves commercial use to its author.

1. **Do not use MIT or Apache for this repo.** Either would purport to grant rights over the derived
   design that we do not hold. The repo's `LICENSE` should mirror the original's terms and name
   them as inherited.
2. **`NOTICE`** crediting Eric Wei, linking the original and its source.
3. **README attribution above the fold**, and the About dialog already carries it in-app.
4. **Third-party inventory**: MediaPipe hand-landmark model (Apache 2.0, Google), Next and React
   (MIT), Inter (SIL OFL). All redistributable; all should be listed.
5. **A public GitHub Pages deploy is non-commercial and therefore fine** — provided the credit ships
   with it, which is exactly what makes P4 a blocker for P5 rather than a nicety.

## P5 — Static export and GitHub Pages

The app is entirely client-side, so it exports cleanly. This also **removes the custom-server
caveat**: the Node HTTPS server becomes a development convenience only, and production is static.

1. `output: 'export'`, `basePath: '/airchord'`, `assetPrefix`, `images: { unoptimized: true }`,
   and a `.nojekyll` file in `public/`.
2. **The known trap: the MediaPipe paths are absolute.** `/mediapipe/wasm` and
   `/mediapipe/hand_landmarker.task` are hardcoded in `vision.ts` and will 404 under a `basePath`.
   They must be prefixed at build time. This is the single most likely thing to break the deploy,
   and it will fail as "the camera works but hand tracking never starts".
3. **CI generates the assets** — `npm run assets` downloads the 7.8 MB model during the build rather
   than committing it.
4. Actions workflow; Pages source set to GitHub Actions.
5. **Verify the deployed site over HTTPS on `github.io`**, which is a secure context, so the camera
   works without any certificate work. The whole mkcert path stays a local-development concern.
6. Optional custom domain later; `basePath` changes if so.

## P6 — CI

1. **On every PR**: typecheck, tests, production build. `main` staying green is what makes two-agent
   work survivable.
2. **The audio check in CI.** It needs headless Chrome and a served build — both available on the
   runners. Worth it: clipping is invisible to every other check.
3. **Cache** `node_modules` and the model download; verify the model checksum.

## P7 — Production metadata

1. **Open Graph and Twitter cards** — this is a visual instrument and will be shared as a link; a
   card image is worth making properly.
2. **Favicon set and web manifest**, theme colour already set.
3. **An error boundary** so a runtime fault shows something intentional.
4. **No analytics.** The About dialog states that nothing leaves your device. Adding any analytics
   would make that false, and the honest options are to keep it true or change the claim. Keep it
   true.
5. **A performance budget** — the model is 7.8 MB and dominates first load. Worth a loading state
   that says so rather than appearing stalled.

## Sequence

**P1 → P0 → P3 → P4 → P5 → P6 → P7.**

P1 today, before any more work lands: two writers, no history, and a tree that does not currently
typecheck. P4 gates P5 — the deploy is where the attribution obligation becomes real. P6 could
follow P5, but is worth pulling forward the moment both lanes are active.
